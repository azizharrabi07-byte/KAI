# KAI — migration and rebrand audit

How this repository was produced from the upstream Coucou Windows implementation, what was
replaced, and how to prove afterwards that nothing upstream leaked in.

## Upstream

| | |
|---|---|
| Project | Coucou — a desktop companion app by Louis Raillé |
| Source | https://github.com/Louis-CFM/coucou |
| Ported subtree | `windows/` (the Tauri 2 / Rust / TypeScript implementation) |
| Pinned commit | `8e12bed56134d2ee7165e73f132646b143ce56e4` — "docs: changelog for Windows CI artifact download" |
| Read-only reference clone | `C:\Users\DELL\Desktop\coucou-source` |
| Code licence | MIT — Copyright (c) 2026 Louis Raillé |
| Brand/asset licence | **Not MIT.** `LICENSE-ASSETS.md`: the names "Coucou" and "Mochi", the Mochi character, the app icon and menu-bar icon, the 28 sounds, and all images/GIFs/videos remain the property of the author. |

That second row is the whole reason for the work below. The upstream author's own `LICENSE-ASSETS.md`
says it directly: *"If you fork Coucou to ship your own app, that's welcome under the MIT License:
just give it your own name, icon, character and sounds."* KAI does exactly that.

## 1. Baseline: the untouched upstream build was proven first

Before any edit, the pristine upstream Windows tree was built end-to-end on this machine:

```
cargo build --release -p coucou-hook   → target/release/coucou-hook.exe
tsc --noEmit && vite build             → dist/ (island + settings bundles)
cargo build --release -p coucou       → target/release/coucou.exe
tauri build                            → bundle/nsis/Coucou_0.1.1_x64-setup.exe (4.02 MiB)
```

Exit code 0. Full log: `docs/evidence/upstream-build.log`. This is the control: the migration is
only meaningful if the starting point actually compiled, and it did.

Note that the upstream Windows tree ships **no audio of its own** — it reads the macOS app's 28 WAVs
through `SOUNDS_DIR` in `vite.config.ts` and copies them into `dist/sounds` at build time.

## 2. What was ported

The whole `windows/` tree: the Rust backend (`src-tauri/`, 13 modules), the Claude Code relay
(`hook/`), and the TypeScript front end (`src/`, 22 modules). Ported as source, then rebranded and
partly rewritten. 76 files, ~1.3 MB.

## 3. What was replaced

### The character (the important one)

The upstream character is drawn procedurally in `windows/src/mochi/` — but it is drawn *as Mochi*:
the same geometry, palette, eye shapes and animation curves as the macOS `BotEngine.swift`, which
`LICENSE-ASSETS.md` reserves as the Mochi character design.

`src/mochi/` was therefore **deleted**, not renamed, and replaced with `src/character/`:

| File | What it is |
|---|---|
| `types.ts` | the **character replacement interface** — the vocabulary the app programs against |
| `engine.ts` | `KaiEngine` — an original character: a squircle "core" with a single horizontal iris band, orbiting ticks, an intake aperture, a hexagonal status chip and its own particle set |
| `minibots.ts` | one engine per pill/grid canvas (same role as before, new renderer) |
| `greeting.ts` | an original launch sequence: core materialises, scan sweep, "KAI" types in, tucks into the island |

Nothing in the new character is traced from the old one. The silhouette is a different shape
(squircle, exponent 4, versus a wide superellipse), the feature is different (one iris band versus
two pill eyes), the palette is different (deep indigo core with a cyan rim, versus cream), and the
particles are different. The **animation logic** (springs, tweens, blinks, slaps, the dizzy-after-
three-slaps rule) was re-implemented; where behaviour is identical it is because the behaviour is
part of KAI's spec, not because code was copied.

The five consumer imports were repointed from `../mochi/*` to `../character/*`; no other file
needed to change. That is the interface working.

### The audio

The 28 WAVs are reserved assets and the Windows tree never carried them anyway. Rather than license
or reproduce them, **KAI ships no audio files at all**: `src/core/sound.ts` synthesises every one of
the 28 named voices at runtime from a recipe table (oscillator waveform, frequency slide, envelope,
optional low-pass, optional noise transient). The `SOUNDS_DIR` plugin was deleted from
`vite.config.ts`, and the built `dist/` contains no `sounds/` directory. Verified:
`find app/dist -iname '*.wav'` → nothing.

### The icons

`src-tauri/icons/` is reserved ("the app icon and menu bar icon"). All five files were regenerated by
`scripts/gen-icons.mjs`, which now rasterises KAI's own mark — the same squircle-and-band shape as
the character — using only `node:zlib`.

### The screenshots

`screenshots/` is reserved ("images, GIFs and videos"). Deleted outright. KAI's README has no
screenshots rather than borrowed ones.

## 5. Rebrand audit — how to prove it

Run from the repository root:

```bash
bash scripts/rebrand-audit.sh     # must print AUDIT CLEAN
```

Result after the migration:

```
TOKEN           FILES   HITS
coucou              0      0
Coucou              0      0
COUCOU              0      0
mochi               0      0
Mochi               0      0
MOCHI               0      0
NotchBuddy          0      0
Notch Buddy         0      0
notchbuddy          0      0
notch-buddy         0      0
notch_buddy         0      0
louisraille         0      0
Louis Raille        0      0
Raill               0      0

--- built artifacts ---
app/dist            0
.wav files          0
AUDIT CLEAN
```

**Why the token list is shaped that way.** The first version of this audit tested
`NotchBuddy` — one capital, no space — and reported 0 while the real leftover sat in
the source as `notchbuddy: "Notch Buddy"` in `app/src/island/hooks.ts`. A grep over a
token list is only as good as the token list, so every upstream token is now listed in
each spelling it actually appears in (case variants, and the spaced form), and
`app/dist` is checked separately as the built artifact.

`notch` on its own is deliberately **not** a token: `NOTCH_W` / `NOTCH_H` in
`src/core/layout.ts` are the display-notch vocabulary (this app runs on a PC with no
notch), not upstream branding.

Also check the built bundle, not just the sources:

```bash
grep -rIo -F -e coucou -e Coucou -e mochi -e Mochi -e "Notch Buddy" app/dist | wc -l   # → 0
find app/dist app/src-tauri/target/release -iname '*.wav' | wc -l                       # → 0
```

The only files in this repository that contain upstream branding are the evidence files in
`docs/evidence/`, which exist precisely to document what upstream looked like:
`branding-inventory.txt` (the pre-migration inventory, 155 matches) and `upstream-build.log`.

## 6. Additions beyond the port

- **The control layer.** Two Rust pollers that read Hermes Agent (`127.0.0.1:8642`) and OpenCode
  (`127.0.0.1:4096`), two island cards, an approval posture driven by OpenCode's pending permission
  queue, and the `opencode_reply_permission` command. See `integrations.md`.
- **A settings key for the Hermes api-server** (`hermes-api-key`), added to the Credential Manager
  allow-list.
- **`core/`** — the KAI Core control-plane service, with 31 passing tests. Since this pass the app's
  chat goes through it (`core/src/server.ts` `POST /chat` → Hermes → model), which is what makes the
  island's chat work without an Anthropic account; with nothing on 8788 the app falls back to its
  original direct-Claude path. `core/` remains optional for every other feature.

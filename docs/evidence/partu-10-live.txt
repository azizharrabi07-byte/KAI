DEFECTS THIS RUN FOUND (each fixed, each re-verified):
- The capability handler refused on the RECORDED availability snapshot, so a lazily
  connected transport looked dead until some unrelated route woke it: Tests 7-9 failed
  with "no transport connected" while the driver and browser were in fact available.
  The guard now PROBES the transport. A snapshot is a memory, not a measurement.
- The capability route could not return an approval, so an approved DESTRUCTIVE/EXTERNAL
  capability could never run even once: the gate was a wall. It now accepts an approval
  the caller holds and the action really executes.
- Probing every capability at Core startup launched a browser and a driver on every boot
  and stopped the unit suite completing; availability is now probed only when asked.
